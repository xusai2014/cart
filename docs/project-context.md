# 电商平台 — 项目要求

> **项目性质：前端一面实作题（Interview Practical）**，不是生产电商平台立项。  
> 官方题面截图：[interview-brief](../media/interview-brief-overseas-product-selection.jpg)  
> 标准：能向客户演示（可交互）；**功能数量不是主要评价依据**，取舍与完整性更重要。  
> 选型参考：[北美 tech/UX](./na-tech-ux-selection.md)（面向海外/北美习惯）  
> [Harness 分析](./frontend-harness-analysis.md) 仅作工程能力延伸练习，**不纳入本面试交付范围**。

## 官方题面要点

- 标题方向：Product Selection Application for Overseas Consumers  
- 用 React 做选购 Web：浏览 → 找商品 → 加入购物车  
- 桌面 + 手机体验都要好；交付达到 client-demo 水准  
- 考察：业务理解、体验判断、有限时间下的优先级取舍（非堆功能）

## 业务场景

面向海外消费者的商品选购 Web 应用。

- 海外消费者 → 英文界面、简洁国际风；50 分钟内优先英文即可
- 核心路径：浏览 → 找商品 → 加入购物车（必须打通）
- 电脑 + 手机都要有良好体验（响应式是硬指标）
- 达到「可向客户演示」：真实可操作，不是静态原型

## 硬性限制

| 项 | 要求 |
| --- | --- |
| 技术栈 | React |
| 时间 | 50 分钟 |
| 允许 | Agent、组件库、公开资料、官方脚手架 |
| 禁止 | 现成商城模板、网站模板、已有项目成品 |
| 数据 | 可模拟；无需后端、登录、真实支付 |

## 交付物（按重要性）

1. 完整源码（干净、可启动）
2. 2–3 分钟录屏（桌面 + 手机真实操作）
3. 简短交付说明（做了什么、验证了什么、已知问题、主要取舍）
4. Agent 协作记录（可选加分）
5. 线上部署（大幅加分）

## 考察权重（取舍依据）

| 维度 | 权重 |
| --- | --- |
| 优先级能力 | 最高 |
| 业务理解 / 体验判断 / 功能正确性 / 交付完整性 | 高 |
| 代码质量 | 中 |
| Agent 使用 | 中低 |
| 线上部署 | 加分项 |

功能数量不是主要评价依据；合理取舍 > 堆功能。

## 功能优先级

### P0（必须）

1. 商品列表（mock，建议 8–12 个）
2. 商品详情（或点击展开）
3. 加入购物车 + 购物车数量/列表
4. 响应式（桌面 + 手机都能看、能点）
5. 基础视觉（干净、国际风）

### P1（有时间再做）

- 搜索 / 简单筛选（类目或价格）
- 购物车增减、删除
- 空状态 / Loading
- 移动端底部导航或购物车悬浮按钮

### P2（直接砍）

登录、支付、订单、复杂推荐、动画特效、完整多语言、后端对接

## 推荐技术（效率优先）

- 脚手架：Vite + React
- UI：Ant Design / MUI / Tailwind + Headless（选最熟的）
- 状态：useState + Context，或 Zustand（不上 Redux）
- 数据：本地 mock 数组
- 响应式：Tailwind 或 CSS media query

## 交付说明结构

1. 已完成内容（核心选购路径）
2. 实际验证场景（桌面加购、手机操作、购物车同步）
3. 已知问题（静态 mock、无搜索、购物车未持久化等）
4. 主要取舍（为何优先响应式与购物车，而非筛选/推荐）

## 加分与避坑

**加分：** 50 分钟内部署到 Vercel/Netlify/GitHub Pages；录屏清晰；组件拆分干净。

**避坑：** 现成商城模板；功能过多导致核心路径有 bug；只做桌面；录屏无真实操作；提交含 `node_modules` 或敏感信息。

## 一句话标准

在严格时间限制下，抓住海外选购核心路径，做出可演示、可响应、有基本购物车逻辑的应用，并清楚说明取舍。以「能向客户演示」为最终标准。
